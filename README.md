# 云运动 GUI｜区间随机数据 · 多账号管理 · 跑步/走路双模式

基于 [Zirconium233/yunForNewVersion](https://github.com/Zirconium233/yunForNewVersion) 合工大云运动跑步脚本扩展的桌面工具。提供多账号管理、跑步与走路模式、History 历史路线下载、路线预览及多账号并行任务，适用于合工大及接口兼容的其他学校。

核心特色是**在用户设定的区间内随机生成运动测试数据**：从已有路线中选择并截取连续路段，生成不同的总时长和带平滑变化的逐点配速，并同步处理累计时间与里程。默认长度为 **2 km**，可在窗口中调整距离、配速、步频和节奏变化，无需反复手动修改 JSON。

## 最新功能

- **Windows exe**：完整下载、解压后双击打开，无需安装 Python。
- **多账号管理**：各账号配置分别保存，支持从自己的请求头一键填写 Token、设备信息和服务器地址。
- **多账号并行**：不同账号可在同一 GUI 内同时运行，每个任务使用独立后台进程。
- **顶部进度条**：位于账号选择框旁，切换账号时显示对应任务的进度。
- **独立任务日志**：在「并行任务」页分别查看状态、进度和日志，支持单独停止。
- **跑步 / 走路模式**：跑步默认平均配速 5～7 分钟/km、步频 170；走路默认平均配速 9 分钟/km、步频 120。
- **路线库与 History**：下载本人历史记录，或导入已有 history / tasklist JSON。
- **随机连续路段**：从足够长的已有路线中截取目标长度，不拼接互不相连的路径。
- **本地预览**：生成后查看路线、配速曲线、里程、时长和步频，再决定是否提交。
- **原始 JSON 回放**：保留原文件参数，兼容原脚本高级菜单。

默认 2 km 是本地生成参数；是否自动结束、服务器如何判定记录，取决于具体接口和版本。本项目不保证所有学校兼容。

## 下载与启动

### Windows exe

在本仓库点击 **Code → Download ZIP**，完整解压。

目前最新版程序和源码位于 **`source/`** 目录：

```text
source/
├─ CloudMotionGUI.exe       ← 双击启动
├─ config.example.ini       ← 空白配置模板
├─ docs/                    ← 图文教程
├─ demo_routes/             ← 人工演示路线
├─ desktop.py
└─ ...
```

进入 `source` 文件夹，双击 **CloudMotionGUI.exe**。如果使用单独下载的 Windows 发布包，直接打开解压目录中的同名 exe。

请完整保留 exe 同目录的模板、教程与演示文件。账号、路线和日志均保存在程序所在目录；更换文件夹启动时，会读取新目录自己的配置。

### 从源码启动

安装带 Tkinter 的 Python，在含有 `setup.ps1` 和 `desktop.py` 的目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
.\start_gui.bat
```

## 第一次使用

### 1. 导入自己的账号信息

按照 **[图文教程](docs/QUICKSTART.md)**，使用 PCAPdroid 捕获自己正常登录后的云运动请求。在请求的 HTTP 页面复制请求头及请求体，然后：

1. 打开 GUI 的「账号管理」，点击「新增账号」。
2. 填写账号或本地标识，点击「从请求头填写」，粘贴捕获的请求。
3. 核对 Token、设备信息、App 版本及服务器基础地址。
4. 点击「保存本机配置」，再点击「检查所选已保存账号」。

请求头通常不包含学号，需要自己填写账号标识。模板中的 `http://127.0.0.1:8088/m-api` 是本机占位地址，不能直接用于访问学校服务器；正常导入请求头后，应核对为自己的实际地址。

本版 GUI 不提供新增的密码自动登录功能。Token 失效后，需要正常登录并重新导入该账号的有效请求头。

### 2. 获取路线

在「History 记录」依次操作：

**获取学期 → 选择学期 → 获取历史列表 → 选择记录 → 下载所选记录到路线库。**

也可在「路线与预览」导入已有 JSON。公开包附带的 `demo_routes` 是位于 `(0, 0)` 附近的人工示例，仅用于了解格式和本地预览，不是实际校园路线。

### 3. 设置参数并预览

在「路线与预览」选择模式、路线来源、距离和配速等参数，然后点击 **「生成本地副本与预览」**。

| 参数 | 说明 |
| --- | --- |
| 距离 | 默认 2 km，可自行设置；源路线必须足够长 |
| 跑步配速下限 / 上限 | 控制随机生成的平均配速区间 |
| 走路平均配速 | 走路模式的目标平均配速 |
| 步频 | 可独立设置，模式切换时填入默认值 |
| 平滑节奏变化 | 调整逐点配速的变化幅度 |
| 随机种子 | 留空时重新随机；填写相同种子与参数、使用相同来源可复现 |

生成操作在本机完成，原路线文件不会被覆盖。修改参数、切换账号或更换路线后，请重新生成预览。

平均配速区间不代表所有逐点配速都处于该区间。App 的轨迹颜色由其自身规则决定，速度有变化也可能呈现相近颜色。

### 4. 执行任务

核对预览中的账号、路线、里程和时长后，点击 **「提交当前预览的数据」**，确认执行。

提交会创建服务器记录；接口返回成功不等于记录最终有效。生成器保留原文件的踩点字段，未重新验证截取后的路线是否经过所有点。跑步 / 走路模式控制本地数据，不会更换服务器的业务任务类型。

## 多账号并行与进度

1. 为第一个账号生成预览并启动任务。
2. 切换顶部账号，给第二个账号选择路线、生成预览并启动。
3. 前一个账号的任务会继续运行；顶部进度条显示当前所选账号的进度。
4. 在「并行任务」页选中任务，可查看独立日志或单独停止。

同一账号在一个 GUI 窗口内同时只允许一个任务。运行时不能修改该账号配置；不要再从另一个 GUI 或 PowerShell 为同一账号重复启动。

顶部「停止所选账号任务」只停止当前账号；关闭窗口时，如仍有任务运行，会提示确认停止全部任务。

## 常见问题

**打开 exe 后没有以前的账号？**

程序读取 exe 所在目录的配置。更新个人使用的版本时，请先等待任务结束并关闭窗口，再将新 exe 放回原来保存账号的文件夹。保留原来的 `config.ini`、`accounts/`、路线和状态文件。

**连接 127.0.0.1 被拒绝？**

当前账号仍使用模板占位地址。重新导入自己的有效请求头，核对实际服务器地址后保存。

**401 认证失败？**

重新正常登录该账号，更新 Token 和对应设备信息。切换 GUI 账号只切换本地配置，不会刷新登录会话。

**全红或全黄的轨迹是否代表异常？**

颜色取决于 App 的配速着色规则，不能仅凭颜色判断数据是否正确或记录是否有效。

**中途断网、合盖或睡眠怎么办？**

程序遇到请求失败会停止，不自动重发未知结果的批次。请先核对 App 中是否有未完成记录，再决定后续操作。Windows 运行期间有空闲睡眠保护，但不覆盖合盖策略或手动睡眠。

## 本机数据与公开发布

公开发布包使用空白配置模板，不包含维护者的账号、密码、Token 或个人路线。以下文件是运行后产生的私人数据，请保存在本机：

```text
config.ini
accounts/
tasks_else/
test_fixtures/
logs/
desktop_state.json
*.pcap
*.pcapng
```

INI 中的凭据是本机明文配置，请自行保护。仅连接有权使用的服务和账号。

## 开发与打包

安装依赖后运行离线测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

生成按白名单整理的公开源码包：

```powershell
.\.venv\Scripts\python.exe .\build_public_release.py
```

生成包含 exe 的 GitHub 更新包与 Windows 发布包：

```powershell
powershell -ExecutionPolicy Bypass -File .\build_exe.ps1
```

打包脚本会检查公开源码中是否混入本机敏感配置，并检查 exe 的界面与后台入口能否启动。离线测试及启动检查不代表所有服务器接口均已完成实测。
